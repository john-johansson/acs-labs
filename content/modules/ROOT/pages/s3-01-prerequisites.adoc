== Access the bastion host

SSH into the bastion host using the credentials from the Showroom dashboard:

[source,bash]
----
ssh lab-user@<bastion-host> -p <port>
----

NOTE: Replace `<bastion-host>` and `<port>` with the values shown on your Showroom dashboard under *Bastion Host*.

== Discover your console URLs

On the bastion, run:

[source,bash]

echo "OpenShift Console: https://$(oc get route console -n openshift-console -o jsonpath='{.spec.host}')"
echo "RHACS Console:     https://$(oc get route central -n stackrox -o jsonpath='{.spec.host}')"

== Verify RHACS CLI access

`ROX_CENTRAL_ADDRESS` and `ROX_API_TOKEN` are already set on the bastion.

[source,bash]
----
export ROX_ENDPOINT="$ROX_CENTRAL_ADDRESS"
roxctl central whoami
----

NOTE: Expected output includes an *Admin* (or equivalent) role. Do not pass `--token`; `roxctl` reads it from the environment.

== Verify the demo application namespaces

This session uses the pre-deployed multi-tier medical application. Confirm the application namespaces exist:

[source,bash]
----
oc get namespace backend payments operations
----

Expected output shows all three namespaces with `Active` status.

Confirm the backend tier (the primary focus for network exercises) is running:

[source,bash]
----
oc get deployment -n backend
----

You should see `api-server`, `backend-atlas`, `varnish`, and `postgres` with available replicas.

Confirm the payments tier:

[source,bash]
----
oc get deployment -n payments
----

You should see `gateway`, `visa-processor`, and `mastercard-processor`.

Confirm the operations namespace (used as an anomalous traffic source):

[source,bash]
----
oc get deployment -n operations
----

You should see `jump-host` (and optionally `puppet-master`).

== Verify the Compliance Operator

Confirm the Compliance Operator is installed and the CIS profiles are available:

[source,bash]
----
oc get csv -n openshift-compliance | grep compliance
----

Expected output shows the Compliance Operator CSV in `Succeeded` phase.

[source,bash]
----
oc get profiles.compliance -n openshift-compliance | grep -E 'ocp4-cis |ocp4-cis-node '
----

You should see both `ocp4-cis` and `ocp4-cis-node` profiles listed.

== Application architecture

The demo environment deploys a medical application across five namespaces. This session focuses on three:

* `backend` (4-tier: varnish :8080 -> api-server :9001 -> postgres :5432 + backend-atlas :8080). The api-server also connects cross-namespace to `payments/gateway`.
* `payments` (gateway :7777 -> visa-processor :8080 + mastercard-processor :8080). Receives cross-namespace traffic from `backend/api-server`.
* `operations` (jump-host :22). Connects cross-namespace to `payments/visa-processor` and `medical/patient-db`, representing unapproved lateral movement.

== Full reset (optional)

If you have run these exercises before on this Showroom and want a clean starting point, run the cleanup script from the cloned repository:

[source,bash]
----
bash scripts/s3-cleanup.sh
----

The script removes lab-created resources (`ScanSettingBinding` and generated `NetworkPolicy` objects). It is idempotent and safe to run multiple times.
On a fresh Showroom you can skip this step.
