= Exercise 7: Network policy generation
:navtitle: Exercise 7: Network policy generation

include::partial$session3-ui.adoc[]

Estimated time: 15 minutes.

RHACS generates 100% standard Kubernetes `NetworkPolicy` manifests. Two downloads use different peer lists, and this exercise compares them.
There are no proprietary sidecars, no custom CRDs, and no vendor lock-in.
If RHACS were uninstalled tomorrow, OpenShift's OVN-Kubernetes CNI would continue enforcing these policies at the kernel level.
The generated YAML can be committed to a Git repository and applied through a GitOps pipeline.

In this exercise you apply a default-deny ingress `NetworkPolicy` for `postgres` from the baseline, then compare that file with *Generate and simulate network policies*.

The anomalous cross-namespace flow is confirmed.
As *Platform Operations*, you keep the `jump-host` probe out of the policy you enforce, and you see why the other button would have allowed it.

By the end of this exercise you will:

* Mark any Exercise 5 `jump-host` to `postgres` probe as anomalous on the `postgres` baseline.
* Download the baseline as a `NetworkPolicy` and confirm it allows only `api-server`.
* Generate a policy from observed flows and see that the same probe can still be allowed.
* Apply the baseline download, not the observed-flow download.

== Task 7.1: Mark the postgres probe as anomalous

Exercise 5 probed `postgres` from `jump-host` to prove baseline alerting.
The policy you apply in this exercise comes from the baseline. Mark the probe anomalous first, or the download will allow it.

. In the RHACS Console, navigate to *Network > Network Graph*.
. Select the `production` cluster and the `backend` namespace.
. Click `postgres`, then open the *Baseline* tab.
. If `operations/jump-host` (or `jump-host`) appears in the baseline list, use the overflow / bulk actions to *Mark as anomalous*.
. If the flow already shows as anomalous (or is absent from the baseline list), leave it.

== Task 7.2: Download the baseline as a network policy

Stay on the `postgres` *Baseline* tab.

. Click *Download baseline as network policy*.
+
This file allows only peers that are still on the baseline. `jump-host` is omitted because you marked it anomalous. The policy name is `stackrox-baseline-generated-postgres`.
. Save the download. You will copy it to the bastion in Task 7.4.
. Confirm the YAML allows ingress only from `app: api-server` on port `5432`. It must not allow `jump-host` or the `operations` namespace.

The intended policy looks like:
+
[source,yaml]
----
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: stackrox-baseline-generated-postgres
  namespace: backend
spec:
  podSelector:
    matchLabels:
      app: postgres
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: api-server
    ports:
    - protocol: TCP
      port: 5432
----
+
This policy allows ingress only from pods with label `app: api-server` on port `5432/TCP`.
All other ingress is denied by default once a `NetworkPolicy` exists for a pod selector.

If `jump-host` is still in this YAML, return to Task 7.1 and mark it anomalous, then download again.

== Task 7.3: Compare with Generate and simulate

*Generate and simulate network policies* is a different list. It allows every connection observed in the graph time window, including anomalous flows. Do not apply that YAML.

. In the graph header, click *Network policy generator*.
. Click *Generate and simulate network policies*.
. Open the `postgres` policy. Its name is typically `stackrox-generated-postgres`.
+
`jump-host` can appear here because of the Exercise 5 probe. That is expected. The connection happened, so this button allows it. Marking the flow anomalous does not remove it from this YAML.
. Close the panel without downloading this file. Task 7.4 applies the baseline download from Task 7.2.

NOTE: Deployments that already have a `NetworkPolicy` will not get a new one from this generator. RHACS does not overwrite existing policies.

TIP: To compare the generated policies with existing ones, click *Compare* in the panel. A side-by-side view shows the YAML for current and generated policies.

== Task 7.4: Apply the baseline policy via CLI

Copy the baseline download from Task 7.2 to the bastion if the browser saved it on your workstation.

[source,bash]
----
oc apply -f ~/stackrox-baseline-generated-postgres.yaml
----

Use the path where you saved the download if it is not `~/stackrox-baseline-generated-postgres.yaml`.

If that file allows `jump-host` or `operations`, do not apply it. From `~/acs-labs`, apply the example file instead:

[source,bash]
----
oc apply -f content/modules/ROOT/examples/stackrox-generated-postgres.yaml
----

If you already applied a generator policy named `stackrox-generated-postgres`, delete it before you continue. Kubernetes combines ingress rules on the same pods, so that policy would keep `jump-host` allowed.

[source,bash]
----
oc delete networkpolicy stackrox-generated-postgres -n backend --ignore-not-found
----

. Verify the policy exists:
+
[source,bash]
----
oc get networkpolicy -n backend
----
+
Expected output includes:
+
[source,text]
----
NAME                                   POD-SELECTOR     AGE
stackrox-baseline-generated-postgres   app=postgres     5s
----

If you used the example file, the name is `stackrox-generated-postgres` instead.

. Confirm the applied YAML allows only `app: api-server`:
+
[source,bash]
----
oc get networkpolicy -n backend -o yaml
----

The OVN-Kubernetes CNI now enforces this policy at the kernel level. Only `api-server` pods can reach `postgres` on port 5432.

== Key takeaways

* The Network Policy Generator produces standard `networking.k8s.io/v1` `NetworkPolicy` manifests, not proprietary resources. OpenShift enforces them natively.
* *Download baseline as network policy* allows only peers that remain on the baseline. That is the policy this lab applies.
* *Generate and simulate network policies* allows every observed connection in the graph time window, including anomalous flows. Use it to see the difference. Do not apply it when the baseline download is the policy you want enforced.
* The baseline download is named `stackrox-baseline-generated-<deployment>`. The observed-flow download is named `stackrox-generated-<deployment>`.
* Policies cannot be applied directly from the RHACS UI. Download the YAML and apply via `oc apply` or commit to Git for GitOps deployment.
* Once a `NetworkPolicy` selects a pod, all ingress not explicitly allowed is denied. This is the Kubernetes default-deny model.
