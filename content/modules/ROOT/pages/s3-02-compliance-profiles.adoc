Estimated time: 10 minutes.

Most organizations treat compliance as a periodic event: a scramble before an audit to collect evidence, run manual checks, and compile spreadsheets.
The Red Hat Compliance Operator shifts that model to continuous, automated scanning.
It runs natively on OpenShift to evaluate core OS node configurations and platform control plane settings against industry benchmarks, without external agents.

A regulatory audit is scheduled for next quarter.
As the *Platform Operations* team, your first task is to enable continuous CIS benchmark scanning on the cluster so that compliance evidence is generated automatically from this point forward.

By the end of this exercise you will:

* List the compliance profiles available on the cluster.
* Deploy a declarative `ScanSettingBinding` that binds the `ocp4-cis` and `ocp4-cis-node` profiles to the default scan settings.
* Monitor scan progress and confirm that `ComplianceCheckResult` CRDs are created.

== Task 1.1: List available compliance profiles

The Compliance Operator ships with several built-in profiles.
Confirm that the CIS profiles are present:

. List installed profiles:
+
[source,bash]
----
oc get profiles.compliance -n openshift-compliance
----
+
Look for `ocp4-cis` (platform controls) and `ocp4-cis-node` (node-level controls) in the output.

+
[source,bash]

[source,bash]

== Task 1.3: Monitor scan progress

The Compliance Operator creates a `ComplianceSuite` and individual `ComplianceScan` resources.
Scans commonly take several minutes on a multi-node cluster. Stay on this task until the suite reaches `DONE`, or use the tip at the end if you need to move on while scans finish.

. Check per-scan progress:
+
[source,bash]
----
oc get compliancescan -n openshift-compliance
----
+
Re-run the command until all scans reach `DONE`.
+
TIP: Optional console view (same data, visual status):
+
--
. Open the OpenShift Console URL from the prerequisites.
. Go to *Operators > Installed Operators* and open the *Compliance Operator* (project `openshift-compliance`).
. From the operator pages, open the compliance resources (*ComplianceScan*, *ComplianceSuite*, and related tabs) and refresh until scans show phase `DONE`.
--

. Check suite-level status:
+
[source,bash]
----
oc get compliancesuite -n openshift-compliance
----
+
Expected output shape (abbreviated):
+
[source,text]
----
NAME             PHASE   RESULT
cis-weekly-scan  DONE    NON-COMPLIANT
----
+
Read both columns. `PHASE` should be `DONE` when scanning finished.
`RESULT` is often `NON-COMPLIANT` on a default cluster (gaps are expected).
You may also see `INCONSISTENT` (nodes disagreed) or `ERROR` (one or more underlying scans could not complete cleanly).
Any of those suite results is fine for this lab as long as check results exist.
The value of continuous scanning is identifying and tracking gaps, not achieving 100% compliance on day one.

. Verify that individual check results were created:
+
[source,bash]
----
oc get compliancecheckresults -n openshift-compliance --no-headers | wc -l
----
+
A non-zero count confirms that the Compliance Operator evaluated applicable controls.

. Summarize check statuses (optional, useful before Exercise 2):
+
[source,bash]
----
oc get compliancecheckresults -n openshift-compliance --no-headers | awk '{print $2}' | sort | uniq -c | sort -rn
----

TIP: If scans are still running, you can proceed to Exercise 2 while they complete.
The pre-deployed `acs-catch-all` schedule still produces Coverage results for non-CIS profiles.
CIS results for this lab come from the `cis-weekly-scan` binding you just applied (and from the UI schedule you create in Exercise 2).

== Key takeaways

* A `ScanSettingBinding` is the declarative link between compliance profiles and scan settings. Applying it triggers scans immediately.
* The Compliance Operator produces `ComplianceScan`, `ComplianceSuite`, and `ComplianceCheckResult` CRDs that capture audit evidence as native Kubernetes resources.
* Suite `RESULT` is often `NON-COMPLIANT` on a default cluster. Treat check-result counts and statuses as the detailed evidence, not a single summary string alone.
